## TL;DR

- **ทำก่อน (ผลต่อสายตาสูงสุด/งานต่ำสุด):** (1) บัลลังก์ Hel + ชั้นวางประกาย — เนื้อเรื่องบท 5 พูดถึงตลอดแต่ในแมพไม่มีอะไรเลย (2) ผนังถ้ำ 3D ทั้งแมพ (Hel's Hollow ก่อน แล้วใช้ชุดเดิมกับ Archive/Roots) — ตอนนี้ผนังถ้ำดูเหมือน "หลุมดำ" ไม่ใช่หินนูน (3) สันหิน + ปากถ้ำ Wolfwood
- **เจอบั๊กระหว่างตรวจ:** แสงใน `arena3d.py:191` มาจาก **ขวาบน (ตะวันออกเฉียงเหนือ)** ไม่ใช่ซ้ายบนตามคอมเมนต์ — เงาธง/ผู้ชมในภาพ `arena_ground.webp` ตกลงซ้ายล่าง สวนกับทุกอย่างในเกม (แก้: `math.radians(-135)`)
- **เจอปัญหาที่ 3D แก้ได้ตรงจุด:** หอคอย CENTRAL CORE ถูกตัดหายไป **58%** ของความสูงภาพ (กล้องเลื่อนขึ้นเหนือขอบแมพไม่ได้) และภาพกว้างแค่ 11.8 ช่องบนฐานชน 15 ช่อง (กำแพงล่องหน ~1.6 ช่องสองข้าง)
- **ไม่แนะนำ:** อบทุ่งหญ้าทั้งแมพ, เปลี่ยนต้นไม้ทั้งป่าเป็น 3D, เปลี่ยนร้านค้าที่วาดไว้สวยแล้วก่อนมีชุดสไตล์ toon ที่ผ่านการทดสอบ
- **ก่อนลงมือชิ้นที่ 2:** แยก `arena3d.py` เป็นชุด `tools/bake3d/` (กล้อง/แสง/วัสดุ/ติดตั้ง/ตัวตรวจภาพบังทางเดิน) + โมดูลเกม `js/bake.js` (โหลดตามแมพ ไม่โหลดตอนบูต)

## 0. ข้อเท็จจริงที่ได้จากการตรวจ (ใช้ตัดสินทุกข้อด้านล่าง)

### 0.1 เรขาคณิตกล้อง — ตัวเลขที่ต้องจำ
| ค่า | ที่มา | ความหมาย |
|---|---|---|
| `R.K = 0.76` | `js/render.js:9` | พื้นถูกบีบแนวตั้ง ×0.76 • กล้องเอียง θ = acos(0.76) = **40.5° จากแนวดิ่ง** (มุมก้มจากแนวนอน 49.5°) |
| 1 ช่อง = 1 ม. = `TILE` 40 px | `js/data.js:7` | |
| ความสูง h เมตร บนจอ | sin θ = 0.65 | = h × 0.65 × 40 = **26 px/ม.** (ไม่ถูกบีบ — สไปรต์ตั้งตรงวาดด้วย `upright()` `render.js:101`) |
| ความสูง h ในภาพพื้น (ก่อนบีบ) | 0.65/0.76 | ยื่นขึ้นเหนือ **0.855 ช่องต่อเมตร** |
| **ความชันปลอดภัย** | atan(1/0.855) | ผิวที่หันไปทางเหนือ **ลาดไม่เกิน ~49°** จะไม่บังพื้นหลังมันเลย (ขนานกับเส้นสายตา) • ผิวหันใต้ (หันหากล้อง) ตั้งดิ่งได้ |
| กล้องไม่เลื่อนเกินขอบแมพ | `render.js:55` `U.clamp(cy, 0, …)` | ของสูงที่อยู่ **ริมขอบเหนือ** จะโดนตัดหัว (จอบนสุด = ขอบแมพ y=0) |

ผลที่ตามมา:
- **แบบ A (อบลงพื้น)** ปลอดภัยเมื่อ "ทุกจุดสูง h ต้องมีช่องที่เดินไม่ได้อยู่เหนือมันอย่างน้อย 0.855h ช่อง" — ใช้ได้กับ: ของเตี้ย (<0.4 ม. → ยื่น <0.35 ช่อง), หน้าผาที่หันใต้, ของที่อยู่บนช่องตัน/น้ำ/ผนังที่หนาพอ, ทุกอย่างที่อยู่ "หลัง" (เหนือ) ช่องตัน
- **แบบ B (สไปรต์ตั้งตรงเรียงความลึก)** จำเป็นเมื่อของสูงอยู่กลางพื้นเดินได้หรืออยู่ด้านใต้ของพื้นเดินได้ (ผู้เล่นต้องเดินไปอยู่ "หลัง" มันได้)
- **ถ้าเรนเดอร์สไปรต์ B ด้วยกล้องเดียวกับเกม (เอียง 40.5°, ออร์โธ, 40 px/ม., ไม่ยืด)** ฐานของวัตถุจะตรงช่องพอดีแบบเดียวกับภาพพื้นของโคลอสเซียม — ต่างจากภาพวาด ChatGPT ปัจจุบันที่เป็นมุมไอโซเมตริก (หมุน 45°) วางบนกริดตรง (เห็นชัดในภาพ `town_tower.png`, `town_gate_e.png`)

### 0.2 บั๊ก/ปัญหาที่เจอ
1. **แสงโคลอสเซียมกลับด้าน** — `tools/arena3d.py:191` `rotation_euler = (42°, 0, 135°)`: ทิศแสงที่ได้ = (-0.47, -0.47, -0.74) คือแสงเดินทางไปทาง **ตะวันตกเฉียงใต้** = มาจาก **ตะวันออกเฉียงเหนือ (ขวาบน)** • ยืนยันด้วยภาพ: เงาธงทิศเหนือตกลง **ซ้ายล่าง** (`crop_ne.png`) • ส่วนในเกม: เงาต้นไม้เยื้องขวา (`sprites.js` `Sprites.shadow(g, x + 3, …)`), เงาสะพาน "เยื้องลงขวา" (`townmap.js` bridge) = แสงซ้ายบน • **แก้:** `math.radians(-135)` (หรือ 225) แล้วเรนเดอร์ใหม่
2. **หอคอย CENTRAL CORE ถูกตัด 58%** — `maps.js:360` ฐาน (13,2) กว้าง 15 ลึก 7 • `sprites.js:1001` จำกัด H = 7×40×2.4 = 672 px → ขอบล่างภาพอยู่ที่จอ y≈284 px แต่สูง 672 px → ส่วนบน 388 px อยู่เหนือขอบแมพ ซึ่งกล้องไม่มีวันเลื่อนไปเห็น (ภาพ `town_tower.png`: เห็นแค่ฐานกับประตู) • และภาพกว้าง 672×447/637 = **471 px บนฐาน 600 px** → ช่องชนว่างเปล่า ~64 px ทั้งสองข้าง
3. **ARMORY กับ PLATING ใช้ภาพเดียวกัน** — `maps.js:78` `BUILDING_ART` (ร้าน 4 ร้าน มีภาพ 3 แบบ)
4. **ภาพทั้งหมดโหลดตอนบูต** — `js/art.js:33–37` วนโหลดทุกไฟล์ใน `manifest.json` ทันที → ภาพอบ 3D ขนาดใหญ่ทุกแมพจะเพิ่มเวลาเข้าเกมของทุกคน ต้องมีทางโหลดตามแมพ
5. **`arena_ground` โหลดช้าแล้วไม่วาดพื้นใหม่** — `art.js:136` วาดพื้นใหม่เฉพาะคีย์ที่ขึ้นต้น `ground_`/`prop_` • ภาพอบใหม่ควรตั้งชื่อ `bake_*` แล้วเพิ่มในเงื่อนไขนี้ (หรือขึ้นต้น `ground_`)
6. **คบเพลิงที่กำลังทำ** วาดก่อนรายการเรียงความลึก (`render.js` ~181 ก่อน `list.sort`) → เปลวไฟฝั่งใต้จะถูกตัวละครที่ยืนชิดกำแพงใต้ทับ (ควรเป็นเปลวไฟทับตัวละคร) — ถ้าจะแก้ ให้ push เข้า `list` ด้วย y ของคบเพลิงแทน

## 2. รายละเอียดทีละข้อ

### #1 บัลลังก์ Hel + ชั้นวางประกาย (Hel's Hollow) — ลำดับ 1

**1) ตำแหน่ง/ไฟล์:** `MAP_DEFS.helcave` NPC Hel ที่ (37,40) `js/maps.js:57` • กลางถ้ำรับประกันพื้นโล่งวงรัศมี 4 รอบ (37.5,37.5) `maps.js:240` • ฟังก์ชันใหม่ `GameMap.placeLandmarks()` เรียกต่อจาก `placeSeamProps()` (`maps.js:916`) + ภาพใน `Sprites.drawBake` (ใหม่) • แสง: ต่อท้าย `map.extraLights` (ถูกรวมใน `render.js:342`)

**2) ทำไม:** บท 5 ทั้งบทยืนบน "ชั้นวางประกาย" (`story.js:25,30,44`, `npc.js:365–402` — "ชั้นวางเหล่านี้คือทุกคนที่ใบไม้ไปไม่ถึง", Kitsura "เผาชั้นวางทีละชั้น") แต่ในเกม Hel ยืนบนพื้นหินเปล่า (`hel_throne.png`) • ฉากนี้เป็นของที่ 3D ทำได้ดีมาก: ชั้นวางหลายร้อยช่อง + โหลแก้วเรืองแสง = งานโมเดลซ้ำ ๆ (array modifier) ที่วาดมือไม่ไหว

**3) แบบ:** **B** สำหรับชั้นวางตั้งอิสระและบัลลังก์ (สูง 2.5–3 ม. กลางพื้นเดินได้ ผู้เล่นเดินอ้อมหลังได้) + **A-decal** สำหรับแท่นยกพื้นวงกลม (สูง ≤0.3 ม.) ที่วาดลงภาพพื้นตรงตำแหน่ง

**4) โมเดล:**
- **แท่น (A-decal):** วงกลม 3 ขั้น รัศมี 3.5/2.8/2.2 ม. สูงขั้นละ 0.1 ม. หินออบซิเดียนขัด + ลายวงจรเรืองฟ้าอมเขียว (`#60f0d0` = สี `glow` ของ look `hel` ใน `sprites.js:847`) ศูนย์กลาง (37.5, 39.5)

**รายละเอียดสำคัญ**
- **กล้องสไปรต์ B:** ทิศเดียวกับกล้องพื้นทุกประการ (เอียง 40.5° yaw 0) เปลี่ยนแค่กรอบ: `ortho_scale = กว้าง(ม.)`, `res_x = กว้าง × 80`, `res_y = ceil((ลึก×0.76 + สูง×0.65) × 80) + pad` • anchor = จุดพื้นใต้-กลางของฐาน (ใช้ `world_to_camera_view` แปลงเป็นพิกเซล) • **ให้ anchor = จุดเรียงความลึก** เสมอ (`upright()` ใน `render.js:101` เลื่อนตาม y ที่ใช้เรียง ถ้าไม่ตรงกันภาพจะลอย)
- **เงาของสไปรต์ B แยกเป็นอีกภาพ:** ใช้ plane `is_shadow_catcher` + `film_transparent` → `*_shd.webp` วาดลงผ้าใบพื้น (multiply) ตอน `renderGround` — ตัวละครที่เดินผ่านจะอยู่ "บน" เงาถูกต้อง แทนวงรีเทาแบบ `Sprites.shadow` (`drawBuildingImg` ใช้วงรีอยู่)
- **ความละเอียด:** A = 40 px/ม. (เท่าผ้าใบพื้น) • B = 80 px/ม. วาด ×0.5 (รองรับ zoom ≤2.2 × dpr 2)
- **meta + hash ผัง:** เกมคำนวณ hash ของ `tiles` ตอนสร้างแมพ เทียบกับ meta — ไม่ตรง = ไม่ใช้ภาพ (กลับไปวาดด้วยโค้ด) + `console.warn`
- **ฝั่งเกม `js/bake.js`:** `Bake.need(mapId)` โหลดตอนเข้าแมพ (ไม่ใส่ในลิสต์บูต — กรอง `bake_` ออกจาก `art.js:36`) • `Bake.ground(map, g)` เรียกใน `renderGround` หลัง `seamArt` • `Bake.props(map)` push ลง `map.props` ชนิด `bake` + `Sprites.drawBake` (วาด 1:1 ตาม anchor, จางเมื่อบังผู้เล่นแบบ `Flora.drawObj`, รองรับชีตหลายเฟรม) • ต่อ `extraLights` • ตั้ง `block` จาก meta แล้วรัน reachability check • หลังวาดลงพื้นแล้ว `delete Art.imgs[k]` คืนหน่วยความจำ
- **เวลาเรนเดอร์:** `--preview` = 8 samples ครึ่งความละเอียด (~1 นาที) ไว้ปรับ • จริง 32 samples + OIDN

## 5. คุมสไตล์ให้เข้ากับภาพวาด (ตัวละคร/มอน/อาคารภาพวาด)

ภาพวาดในเกม: เส้นขอบเข้มหนา, แสงเงาเป็นขั้น (cel), สีอิ่ม, ไฮไลต์ขอบ, แสงซ้ายบน • ภาพ 3D ตอนนี้ (arena): ไม่มีเส้น, ไล่เงานุ่ม, สีซีด → เห็นชัดว่าคนละสไตล์ (`arena_south.png`)

1. **ทิศแสงเดียวทั้งเกม:** key ซ้ายบน (azimuth −135°, elevation 40–45°) — แมพที่ `SKY` บอกแสงจากขวา (mistlake เย็น / wolfwood จันทร์ — `render.js:395`) ใช้เป็น **rim light สีตามแมพจากขวา** ไม่ใช่ key (เงาต้องตกขวาล่างเหมือนสไปรต์ทุกตัว)
2. **เส้นขอบ:** Freestyle (มีใช้แล้วใน `render_blender.py:129–138`) — silhouette + border + crease มุม >60°, สีน้ำตาลเข้ม (0.08,0.05,0.04) ไม่ใช่ดำสนิท, หนา ~1.5 px ที่ 1× (3 px ที่ 2×) • ภาพพื้น A ใช้เส้นบางกว่า (1 px) ไม่งั้นหินทั้งแมพจะดูเป็นลายเส้นการ์ตูนเกิน
3. **แสงเป็นขั้น (Cycles ไม่มี Shader-to-RGB):** ทำใน compositor — แยก pass Diffuse Direct → ColorRamp แบบ Constant 3 ขั้น → คูณ Diffuse Color + Glossy + Emission + AO • หรือแบบง่าย: แสงหลักแรง/ambient ต่ำ + look `Medium High Contrast` (แบบ toon ใน `render_blender.py:130`)
4. **ผิวภาพวาด:** compositor **Kuwahara** (anisotropic, ขนาด 4–6 px ที่ 2×) ทำให้ผิว CG เป็นแปรง + เพิ่ม saturation ~1.15 • ตัดรายละเอียดเล็กที่ภาพวาดไม่มี (รอยสึก/ลายไม้ละเอียด)
5. **พาเลตต์กลาง:** ดึงสีจากของที่มีอยู่ — ทอง `#d7b25a`, เรืองฟ้า `#5fd4ff` (TownArt), ม่วงคริสตัล `190,120,255`, ทอง Archive `255,205,100`, ส้ม Roots `255,140,70`, เขียว Hel `#60f0d0` → อยู่ใน `mats.py` ชุดเดียว
6. **ใช้ texture ของเกมเอง** (`ground_cave/road/dirt/grass.webp`) เป็นวัสดุพื้นในฉาก 3D → รอยต่อระหว่างส่วนอบกับส่วนโค้ดไม่สะดุด
7. **กติกาตรวจ:** ทุกงานใหม่ให้ถ่ายภาพจอในเกมเทียบกับตัวละคร 2 ตัว (Class ภาพวาด + มอน) ก่อนติดตั้ง และเก็บ "การ์ดสไตล์" (ภาพตัวอย่างค่ากลาง) ใน `tools/bake3d/README`
8. **ไม่ใช้ 3D กับตัวละคร/แอนิเมชันโครงกระดูก** ตาม CLAUDE.md (Rig ถูกยกเลิก) — ของที่เคลื่อนไหวในรายงานนี้ (น้ำพุ, วงล้อ, ผู้ชม) เป็น **ภาพทีละเฟรม** ทั้งหมด
